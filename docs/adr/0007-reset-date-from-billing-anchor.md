# 갱신 예정일은 API 응답이 아니라 설정 파일의 구독 시작일로 계산한다

포함 크레딧은 "구독을 시작한 날과 같은 날"에 매월 리셋되고, 그 달에 그 날이 없으면 그 달 마지막 날이 기준이다(예: 31일 구독 → 9월 30일, 기준일 31은 유지되어 10월 31일). 처음에는 응답의 `period.ending_at` 날짜를 그대로 쓰기로 했지만, 실사용에서 `ending_at`이 롤링 윈도우의 끝 = 관측 시각이라 **갱신 예정일이 항상 오늘 날짜로 표시되는 오류**가 확인됐다. 구독 시작일을 노출하는 API도 없으므로, 제공 크레딧(Pool)과 같은 방식으로 설정 파일의 `billing_day_of_month`를 근거로 `BillingCycle`이 다음 갱신일을 계산한다. 대안인 "사용량 급감 감지로 리셋 추정"은 서버 지연·백오프에 취약해 배제했다.
